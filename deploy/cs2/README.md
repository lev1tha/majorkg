# CS2-сервер для MAJOR KG

Как поднять игровой сервер на своей машине в дата-центре и подключить его
к платформе, чтобы после вето карта выкатывалась одной кнопкой.

Файлы: [`install.sh`](install.sh) · [`run.sh`](run.sh) ·
[`cs2@.service`](cs2@.service) · [`cs2.env`](cs2.env) ·
[`server.cfg.example`](server.cfg.example)

---

## Что брать в ДЦ

Сервер CS2 упирается не в количество ядер, а в **частоту одного**: движок
считает мир в один поток. Восемь медленных ядер проиграют двум быстрым.

| | Минимум | Комфортно |
| --- | --- | --- |
| CPU | 4 ядра от 3.6 GHz | 6–8 ядер от 4.0 GHz |
| RAM | 8 ГБ | 16 ГБ |
| Диск | 80 ГБ SSD | 160 ГБ NVMe |
| Канал | 100 Мбит | 1 Гбит |
| ОС | Debian 12 / Ubuntu 22.04+ | — |

Ниже 3.6 GHz начинается «резина»: выстрелы регистрируются с задержкой, и
игроки это чувствуют сразу, даже если пинг низкий.

Одна такая машина тянет **2–4 матча одновременно**. Считайте по сетке: на
турнир из 16 составов в первом раунде нужно 8 серверов — либо несколько
машин, либо матчи идут волнами.

### О чём спросить дата-центр

- **Белый IP** и открытые порты `27015–27035` по UDP и TCP.
- **Пиринг в KG-IX.** Это важнее всего остального. Без него трафик до
  абонентов Megaline, Saima и Aknet может пойти кругом через Москву — и
  пинг будет 60 мс из соседнего района. Спрашивайте прямо: «вы в KG-IX?»
- **Реальная частота CPU**, а не «Xeon». Старые серверные Xeon часто
  работают на 2.2–2.6 GHz и для CS2 не годятся.
- Виртуализация: **KVM**, не OpenVZ. На OpenVZ соседи по машине съедят
  ваши такты в самый неподходящий момент.

Альтернатива — **Алматы**: 10–25 мс от Бишкека, а выбор машин и цены там
заметно лучше. Разницу между 3 и 20 мс игрок не заметит, между 20 и 70 —
очень даже.

## Установка

На чистой машине, от root:

```bash
git clone https://github.com/lev1tha/majorkg.git /root/majorkg
bash /root/majorkg/deploy/cs2/install.sh
```

Скрипт ставит зависимости, заводит пользователя `steam`, качает SteamCMD
и саму игру (`app_update 730`, десятки гигабайт — это надолго), кладёт
обёртку запуска и открывает порты.

Скрипт идемпотентен: повторный запуск обновляет игру и не трогает уже
заведённые инстансы. Этим же он и обновляет сервер после патчей Valve.

## Токен GSLT

Без него сервер поднимется, но **игроки из интернета на него не зайдут**.

1. Открыть <https://steamcommunity.com/dev/managegameservers>
2. App ID — `730`, любое имя в memo
3. Скопировать токен

Токен **нельзя делить между серверами**: второй инстанс с тем же токеном
молча откажется пускать игроков. На каждый сервер — свой.

```bash
cp /root/majorkg/deploy/cs2/cs2.env /etc/default/cs2
nano /etc/default/cs2        # вписать GSLT_1, GSLT_2, …
chmod 600 /etc/default/cs2
```

## Конфиг сервера

```bash
cp /root/majorkg/deploy/cs2/server.cfg.example \
   /home/steam/cs2/game/csgo/cfg/server.cfg
nano /home/steam/cs2/game/csgo/cfg/server.cfg
```

Обязательно поменять `rcon_password` — этим паролем платформа выкатывает
карту после вето. Остальное уже настроено под регламент MR12 с овертаймом
и записью демок.

## Запуск

```bash
cp /root/majorkg/deploy/cs2/cs2@.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now cs2@1
```

Номер в имени юнита задаёт порты, поэтому несколько серверов на одной
машине заводятся без правки файлов:

| Юнит | Игра и RCON | SourceTV |
| --- | --- | --- |
| `cs2@1` | 27015 | 27020 |
| `cs2@2` | 27016 | 27021 |
| `cs2@3` | 27017 | 27022 |

```bash
systemctl enable --now cs2@2      # второй сервер
journalctl -u cs2@1 -f            # смотреть лог
systemctl restart cs2@1           # перезапуск
```

Если сервер не стартует, запустите обёртку руками — ошибка будет видна
сразу, без копания в журнале:

```bash
sudo -u steam bash -c 'set -a; . /etc/default/cs2; /home/steam/cs2/run.sh 1'
```

## Подключить к платформе

1. Войти в админку → **Серверы** → «Добавить сервер»
2. Заполнить адрес, порт и **тот же `rcon_password`**, что в `server.cfg`

После этого платформа:

- спрашивает состояние по **A2S** — тем же запросом, которым это делает
  браузер Steam. В списке видно живую карту и число игроков, а «оффлайн»
  означает, что сервер действительно не ответил;
- после вето выкатывает на сервер карту, режим и пароль лобби по
  **RCON** — судье не нужно заходить по ssh посреди турнира.

Пароль RCON хранится только в базе бэкенда и наружу не отдаётся: в ответах
API есть лишь признак, настроен он или нет.

### Про безопасность RCON

Протокол RCON передаёт пароль **открытым текстом**. Пока сервер и
платформа в одном ДЦ — не страшно. Если сервер снаружи, закройте порт
RCON всем, кроме адреса платформы:

```bash
ufw delete allow 27015:27035/tcp
ufw allow from <IP_платформы> to any port 27015:27035 proto tcp
```

UDP (сама игра) при этом остаётся открытым для всех — иначе игроки не
подключатся.

## Проверка

```bash
# сервер отвечает на запрос состояния
ss -lunp | grep 2701

# и виден снаружи — с любой другой машины
curl -s "https://api.steampowered.com/IGameServersService/GetServerList/v1/?key=<STEAM_API_KEY>&filter=addr\<IP\>"
```

Проще всего: в игре открыть консоль и ввести `connect <IP>:27015`. Если
пускает — всё работает, можно добавлять в админку.
